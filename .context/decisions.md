## 2026-04-08 - 采用 MVP 优先路线

- 背景：项目当前只有一份全局计划文档，完整方案包含终端、可视化、场景、文档、GitHub 教学、OAuth、数据库、Docker 沙盒和部署等多个子系统。
- 决策：先实现可演示 MVP，不直接一次性落地完整 15 周路线图。
- 理由：MVP 能最快验证核心学习体验，也能降低基础设施和复杂 Git 沙盒过早引入带来的风险。
- 约束：第一阶段只做核心 Playground 闭环；认证、数据库、Docker 沙盒、完整 GitHub 教学与文档系统暂缓。
