# 风险台账

| 风险 | 触发条件 | 影响 | 缓解策略 |
| --- | --- | --- | --- |
| 范围过大 | 同时启动终端、Git 引擎、可视化、认证、数据库、沙盒和文档系统 | 进度失控，核心体验迟迟不可演示 | 先做 MVP，只保留 Playground 闭环 |
| Git 真实语义复杂 | 过早接入完整真实 Git 行为或 Docker 沙盒 | 调试成本高，状态同步困难 | 先用受控状态模型模拟基础命令，再逐步替换为 `isomorphic-git` |
| 可视化与状态不一致 | 命令处理器和可视化组件各自维护状态 | 用户学习体验混乱 | 以单一 Git state store 作为所有视图的数据源 |
| 依赖和环境复杂 | OAuth、PostgreSQL、Docker Desktop、WSL/browsing companion 等本地依赖不稳定 | 初始化受阻，开发反馈变慢 | 把外部依赖推迟到 MVP 后，先做纯前端可运行版本 |
| 中文/英文国际化过早复杂化 | 一开始就铺完整 next-intl 内容体系 | 复制和路由维护成本升高 | 先保留可国际化结构，MVP 内容以中文为主 |
